Google Apps Script(.gs) 프로젝트를 이 뷰어(gs-flow-viewer)가 읽을 수 있는 `diagrams.md`로 변환해줘.

## 입력

현재 작업 디렉토리(또는 사용자가 지정한 경로) 아래의 모든 `.gs` 파일을 찾아서 읽는다.
각 파일에서 다음을 파악한다.

- 진입점(트리거): `doPost`, `doGet`, 시간 기반 트리거, 메뉴 실행 함수 등
- 분기: if/switch로 갈리는 조건과 그 결과
- 외부 호출: Monday API, Google Chat webhook, Sheets 읽기/쓰기, 다른 GAS 파일 함수 호출
- 종료 지점: 성공 응답, 오류 처리, 알림 발송

## 출력: `diagrams.md`

이 뷰어의 저장소 루트(= `server.js`와 같은 디렉토리)에 `diagrams.md` 파일을 만든다.
`server.js`는 `## 제목` 다음에 오는 첫 번째 ` ```mermaid ` 코드블록만 파싱하므로, 형식을 정확히 지켜야 한다.

```
## 전체 구조

​```mermaid
flowchart TD
  ...
​```

## <파일이 있던 상대 경로>/<파일명.gs>

​```mermaid
flowchart TD
  ...
​```
```

규칙:

- **첫 섹션은 반드시 `## 전체 구조`**로 시작한다. 뷰어가 이 섹션을 개요(overview)로 인식한다.
- 이후 섹션은 파일 하나당 하나씩, `## <경로>/<파일명>` 형식의 제목을 쓴다. 경로에 폴더가 여러 단계면 `/`로 구분해 그대로 쓴다.
- `전체 구조` Mermaid 안에서 각 파일을 가리키는 노드의 라벨 텍스트는 해당 파일의 상세 섹션 제목의 **마지막 경로 구간(파일명)과 정확히 일치**시킨다. 그래야 전체 구조에서 파일 노드를 클릭했을 때 상세 화면으로 자동 이동한다(뷰어가 라벨 문자열로 파일을 찾는다).
- 노드 라벨은 **함수명이 아니라 실무 언어**로 쓴다. 예: `updateStatus()` 대신 "상태 변경 감지", `sendChatMessage()` 대신 "Google Chat 알림 발송". 사람이 소스코드를 몰라도 흐름을 읽을 수 있어야 한다.
- 분기점은 `{...}` 마름모 노드로, 종료는 `([...])` 또는 `[...]`로 표현한다. Mermaid `flowchart TD` 문법을 따른다.
- 같은 파일이 여러 프로젝트 폴더에 복사되어 있으면(예: 공용 유틸이 여러 GAS 프로젝트에 중복 배치된 경우) 상세 섹션도 경로별로 각각 만든다. 뷰어는 제목(전체 경로) 기준으로 구분하고, 사이드바에는 파일명 기준으로 중복 제거해서 보여준다.

## 출력(선택): `public/boards.config.js`

`.gs` 코드에서 특정 서비스/보드/시트 ID가 여러 곳에서 반복 등장해서 "무엇이 어느 보드/서비스와 연결되는지" 색으로 구분하면 유용하겠다고 판단되면, `public/boards.config.js`를 아래 형식으로 채운다. 필요 없다고 판단되면 건드리지 않는다(빈 상태가 기본값이며 정상 동작한다).

```js
window.BOARDS_CONFIG = {
  boards: {
    exampleBoard: {
      id: 'exampleBoard',
      name: '표시용 이름',
      mondayName: '실제 보드/서비스 이름',
      boardId: '해당 ID(선택)',
      color: 'oklch(0.62 0.15 305)',
      soft: 'oklch(0.93 0.04 305)',
      webhook: true,
      webhookNote: '이 보드에서 오는 웹훅/트리거 설명',
    },
  },
  boardAliases: [
    { keys: ['다이어그램 라벨에 등장하는 소문자 키워드'], board: 'exampleBoard' },
  ],
  fileBoardMap: {
    '파일명.gs': ['exampleBoard'],
  },
};
```

## 완료 후

`node server.js`로 로컬 서버(기본 http://localhost:4747)를 띄우고, 사이드바에 `전체 구조`와 파일 목록이 정상적으로 뜨는지, 전체 구조에서 파일 노드를 클릭하면 상세로 이동하는지 직접 확인한다.
